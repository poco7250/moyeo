# moyeo PRD — 친구 모임 관리 웹앱

## Context

친구 모임은 보통 **1차 밥 → 2차 볼링 or 보드게임** 패턴으로 굴러간다. 이때 매번 반복되는 귀찮음이 있다.

- 단톡방에서 "누구 와?" 물어보고 답 안 하는 사람 쫓아다니기
- 1차만 온 사람, 2차부터 온 사람 섞여서 정산이 꼬임
- "꼴찌가 2차 쏘기" 같은 벌칙을 하지만 결과가 정산에 수동으로 반영됨
- 사다리·꽝뽑기는 각자 다른 앱을 켜서 하고, 기록은 안 남음

**moyeo의 한 줄 정의:** "모임 공지 → 참석 → 놀기(게임) → 정산"을 **하나의 링크**로 끝내는 모바일 웹앱.
핵심 차별점은 **게임 결과가 정산에 자동으로 연결된다**는 것.

---

## 1. 목표 & 지표

| 구분 | 목표 | 지표 |
|---|---|---|
| 참석 확인 | 단톡방 "누구 와?" 제거 | 모임 생성 후 24h 내 응답률 ≥ 80% |
| 정산 | 모임 끝나고 10분 안에 정산 완료 | 모임 종료 → 정산 확정까지 중앙값 |
| 재미 | 게임을 moyeo 안에서 | 모임당 게임 실행 횟수, 게임→정산 연동 비율 |
| 리텐션 | 같은 그룹의 재사용 | 그룹당 월 모임 생성 수, 4주 재방문율 |

**Non-goal (지금은 안 함):** 장소 예약/결제 대행, 공개 모임 매칭(소모임·문토류), 채팅 기능(단톡방 대체 X — 단톡방에 링크를 뿌리는 구조).

---

## 2. 타겟 & 페르소나

- **총무형(호스트)** — 모임 만들고 정산까지 떠안는 사람. 가장 큰 페인 보유. 핵심 사용자.
- **참여형(게스트)** — 링크 눌러 참석만 누르고 싶은 사람. **가입 폼을 강요하면 이탈** → 카카오 원탭 로그인으로 진입 비용 최소화.
- 규모: 4~12명 고정 친구 그룹, 월 1~4회 모임.

---

## 3. 핵심 사용자 흐름

```
[호스트] 그룹 생성 → 모임 생성(날짜/장소/차수) → 카톡으로 링크 공유
[게스트] 링크 접속 → 카카오 로그인(원탭) → 그룹 자동 가입 → 차수별 참석 응답
        ↓ (마감 전 미응답자 리마인드)
[당일]  체크인 → 1차 지출 등록 → 2차 볼링 점수 입력 / 사다리·꽝뽑기
        ↓ (게임 결과 → "벌칙: OO가 2차 50% 부담" 자동 반영)
[종료]  정산 확정 → 송금 링크 공유 → 입금 체크 → 기록/명예의 전당
```

## 4. 기능 요구사항

우선순위: **P0 = MVP 필수 / P1 = 출시 직후 / P2 = 이후**

### 4.1 그룹(크루)

| ID | 기능 | 우선순위 |
|---|---|---|
| G-1 | 그룹 생성, 초대 링크 발급(만료/재발급) | P0 |
| G-2 | 멤버 목록, 그룹 내 닉네임/프로필 이모지 | P0 |
| G-3 | **카카오 로그인** 후 초대 링크로 그룹 자동 가입(카카오 닉네임·프로필 기본값, 그룹 내 닉네임 변경 가능) | P0 |
| G-6 | 카카오 계정 없는 친구용 임시 게스트(닉네임 + 기기 토큰, 참석 응답만 가능) | P2 |
| G-4 | 역할: 방장 / 총무 / 멤버 | P1 |
| G-5 | 그룹 기본 송금 계좌·토스/카카오페이 링크 저장 | P1 |

### 4.2 모임 & 참석

| ID | 기능 | 우선순위 |
|---|---|---|
| M-1 | 모임 생성: 제목, 날짜·시간, 장소(지도 링크), 메모 | P0 |
| M-2 | **차수(라운드) 구성**: 1차 밥 / 2차 볼링 / 3차 보드게임 등 템플릿 제공 | P0 |
| M-3 | **차수별 참석 응답**: 참석 / 불참 / 미정 + "늦참(2차부터)", "1차만" | P0 |
| M-4 | 응답 마감 시간, 현황판(누가 왔고 누가 안 눌렀는지) | P0 |
| M-5 | 날짜 후보 투표(When2meet식) — 날짜 미정일 때 | P1 |
| M-6 | 미응답자 리마인드(카톡 공유 문구 생성 / 웹 푸시) | P1 |
| M-7 | 당일 체크인(도착 체크) → 실제 참석자 확정 | P1 |
| M-8 | 노쇼 기록 → 통계 반영 | P2 |

> 설계 포인트: **참석 데이터 = 정산 데이터의 기본값.** 차수별 참석자가 그대로 정산 분배 대상이 된다.

### 4.3 게임 & 벌칙

| ID | 기능 | 우선순위 |
|---|---|---|
| R-0 | **게임 방(로비)**: 진행자가 게임 생성 → 참가자 각자 폰으로 입장 → 전원 준비 시 시작 | P0 |
| R-1 | **사다리 타기**: 참가자 자동 로드, 결과 항목 입력(꽝/벌칙/당첨), 모두의 폰에서 같은 애니메이션 동시 재생 | P0 |
| R-2 | **꽝뽑기(제비뽑기)**: N장 중 꽝 K장, 각자 자기 폰에서 카드 1장 선택 → 전원 뽑으면 동시 공개 | P0 |
| R-3 | 룰렛 / 랜덤 순서 정하기(볼링 레인 순서, 보드게임 선) | P1 |
| R-4 | **벌칙 프리셋**: 금액형(고정 금액 / 비율 — 4.4 벌칙 정산 규칙 참고)·행동형(“다음 모임 장소 예약”) | P0 |
| R-5 | **게임 결과 → 정산 연동**: 금액형 벌칙 당첨 시 해당 차수 정산에 자동 반영 | P0 |
| R-6 | 볼링 점수 입력 → 순위 산출 → 꼴찌/하위 N명 자동 벌칙 | P1 |
| R-7 | 보드게임 승패 기록(게임명, 순위) | P1 |
| R-8 | 이탈자 처리: 제한 시간 내 안 뽑으면 남은 카드 자동 배정, 재접속 시 상태 복구 | P0 |

**게임 진행 방식: 각자 폰.** 게임 상태(대기 → 진행 → 공개 → 종료)는 서버가 관리하고 WebSocket으로 모든 참가자에게 브로드캐스트한다.

**공정성 요구사항 (중요):**
- 결과(사다리 연결, 카드 배치)는 **게임 시작 시점에 서버에서 생성**하고, 클라이언트에는 공개 시점 전까지 보내지 않는다.
- 꽝뽑기에서 "카드를 고르는 행위"는 연출이고, 실제 결과는 서버가 미리 섞어둔 배열의 위치로 결정된다. 같은 카드를 동시에 고르면 먼저 도착한 요청이 가져간다(낙관적 락).
- 실행 시각·참가자·결과를 기록으로 남기고, "다시 돌리기"는 가능하되 **재실행 이력이 모두에게 보인다** (조작 의심 방지 = 친구 사이 신뢰).

### 4.4 정산

| ID | 기능 | 우선순위 |
|---|---|---|
| S-1 | 차수별 지출 등록: 금액, 결제자, 메모(영수증 사진 P1) | P0 |
| S-2 | 분배 기본값 = 해당 차수 참석자 N빵 | P0 |
| S-3 | 개별 조정: 특정인 제외, 고정 금액, 비율(술 안 마심 등) | P0 |
| S-4 | 벌칙 반영 내역 표시("민수: 사다리 꽝 → 2차 +15,000원") | P0 |
| S-5 | **송금 최소화**: 누가 누구에게 얼마 보내면 끝나는지 최소 송금 경로 계산 | P0 |
| S-6 | 송금 체크(보냈어요 → 받은 사람 확인), 미입금 리마인드 | P0 |
| S-7 | 토스/카카오페이 송금 딥링크, 계좌 복사 | P1 |
| S-8 | 원 단위 처리 규칙(100원 단위 올림, 올림으로 더 걷힌 금액은 결제자 몫에서 차감) | P0 |
| S-9 | 회비 통장 모드(그룹 잔액 관리) | P2 |

**벌칙 정산 규칙 (고정 금액 + 비율 둘 다 지원):**

| 유형 | 의미 | 예시 |
|---|---|---|
| `FIXED_AMOUNT` | 정해진 금액을 벌칙자가 부담 | "꽝 걸린 사람 2만원 부담" |
| `RATIO` | 대상 금액의 N%를 벌칙자가 부담 | "꼴찌가 2차 30% 부담" |
| `FULL` | 대상 금액 전부 부담 (`RATIO 100%`의 단축 프리셋) | "꼴찌가 2차 쏘기" |

- **대상 범위:** 차수 전체(예: 2차 볼링 총액) 또는 특정 지출 항목(예: 2차 음료값)을 고른다.
- **나머지 분배:** 벌칙자 부담분을 먼저 떼고, 남은 금액은 **벌칙자를 뺀** 참석자끼리 기본 분배 규칙대로 나눈다.
  - 예) 2차 4명 100,000원, 민수 `RATIO 30%` → 민수 30,000원 / 나머지 3명 70,000원 ÷ 3 = 23,400원(100원 올림, 더 걷힌 200원은 결제자 몫에서 차감)
- **상한:** 고정 금액이 대상 금액보다 크면 대상 금액까지만 부담한다(그 차수에서 남이 돈을 받는 일은 없음).
- **벌칙 여러 개:** 같은 대상에 벌칙이 여러 개면 적용 순서대로 차감하고, 벌칙 합계는 대상 금액을 넘을 수 없다. 넘으면 정산 확정 전에 경고한다.
- **지출 등록 전 벌칙:** 게임이 지출보다 먼저 끝나도 벌칙은 "대기" 상태로 저장했다가 대상 지출이 등록되면 자동 적용된다.

**정산 계산 순서:**
1. 차수별(또는 지출 항목별) 지출 합계
2. 벌칙 부담분 차감(`FIXED_AMOUNT`/`RATIO`/`FULL`, 상한 적용)
3. 남은 금액을 벌칙자 제외 참석자에게 기본 분배(가중치/제외 반영)
4. 결제자별 받을 돈 − 낼 돈 = 순잔액
5. 송금 최소화 알고리즘으로 송금 목록 생성

### 4.5 기록 & 재미 요소

| ID | 기능 | 우선순위 |
|---|---|---|
| H-1 | 모임 히스토리(언제, 누가, 얼마, 무슨 게임) | P1 |
| H-2 | **명예의 전당/불명예의 전당**: 꽝 최다, 볼링 최고점, 출석왕, 지각왕 | P1 |

## 5. 화면 구성 (모바일 우선)

1. **그룹 홈** — 다가오는 모임, 지난 모임, 명예의 전당 요약
2. **모임 상세** — 탭: `참석` / `게임` / `정산`
   - 참석 탭: 차수별 응답 현황판, 내 응답 버튼
   - 게임 탭: 사다리 / 꽝뽑기 / 룰렛 / 볼링 점수 카드, 결과 로그
   - 정산 탭: 지출 목록 → 1인당 금액 → 송금 목록 → 입금 체크
3. **게임 실행 화면** — 풀스크린, 한 폰을 돌려가며 써도 되는 큰 UI
4. **초대 진입 화면** — 링크 접속 시 "OO 모임에 초대받았어요" + 카카오 로그인 버튼 하나 → 로그인 후 바로 참석 응답 화면

## 6. 비기능 요구사항

- **모바일 웹 우선 + PWA**(홈 화면 추가, 웹 푸시). 앱 설치 강요 안 함.
- **카카오톡 공유**(OG 태그 미리보기: "토요일 모임 · 5/8명 참석") — 바이럴 핵심 경로.
- **구조: SPA + REST API.** Spring Boot는 JSON API와 WebSocket만 맡고, 화면은 별도 SPA(React 계열)가 담당한다. 카톡 공유 미리보기용 OG 태그는 SPA가 못 만들어주니까 초대/모임 링크 경로는 서버에서 OG 메타만 담은 HTML을 내려준다.
- **인증: 카카오 로그인(OAuth2).** 백엔드가 카카오 인가 코드를 받아 회원 조회/생성 후 자체 토큰(Access + Refresh, `HttpOnly` 쿠키)을 발급한다. 카카오톡 인앱 브라우저에서 로그인이 깨지지 않는지 꼭 확인해야 한다.
- 초대 링크로 들어온 사람은 로그인 직후 원래 링크로 돌아가 그룹에 자동 가입된다. 금융 정보(계좌)는 그룹 멤버에게만 노출.
- **실시간: MVP부터 WebSocket(STOMP)** — 게임 방(로비/진행/공개)은 필수. 참석 현황·정산 현황 갱신도 같은 채널을 쓴다. 끊겼다 다시 붙으면 REST로 현재 상태를 받아 복구한다.
- 금액은 정수(원) 처리, 부동소수점 금지. 비율 벌칙은 계산 후 원 단위 처리 규칙(S-8)을 적용한다. 정산 확정 후 수정 시 이력 남김.
- 정산/게임 결과 저장은 트랜잭션 처리, 동시 응답 충돌 시 낙관적 락.

## 7. 데이터 모델 초안

```
Member(kakaoId) ─┬─< GroupMember >── Group ─< InviteLink (token, expiresAt)
                 │                     └─< Meeting ─< Round(차수: 밥/볼링/보드게임)
                 │                                     ├─< Attendance (member, status, checkedIn)
                 │                                     ├─< Expense (payer, amount, memo)
                 │                                     │     └─< ExpenseShare (member, amount, weight, excluded)
                 │                                     └─< GameSession (type: LADDER/DRAW/ROULETTE/BOWLING,
                 │                                           │           status: WAITING/PLAYING/REVEALED/CLOSED, version)
                 │                                           ├─< GameParticipant (member, ready, pickedSlot)
                 │                                           ├─< GameResult (member, outcome, rank/score)
                 │                                           └─> Penalty (kind: MONEY/ACTION,
                 │                                                        moneyType: FIXED_AMOUNT/RATIO/FULL,
                 │                                                        amount | ratio, targetRound | targetExpense,
                 │                                                        status: PENDING/APPLIED)
                 └─ Settlement (meeting, status, confirmedAt) ─< Transfer (from, to, amount, sentAt, confirmedAt)
```

- 기존 `member` 패키지(`Member` 엔티티, 이메일·비밀번호 회원가입)는 **카카오 로그인 기반으로 전환**한다. 비밀번호 필드와 `PasswordEncoderConfig`는 걷어내고 `kakaoId`, 닉네임, 프로필 이미지를 저장한다.
- 그룹 안에서의 닉네임은 `GroupMember`에 따로 둔다(그룹마다 다른 별명 가능).

## 8. 릴리즈 로드맵

| 단계 | 범위 | 검증 질문 |
|---|---|---|
| **MVP (v0.1)** | 카카오 로그인, 그룹·초대링크, 모임·차수·차수별 참석, 게임 방(WebSocket) + 사다리·꽝뽑기(각자 폰), 벌칙 프리셋(고정/비율/전액), 정산(N빵·조정·벌칙연동·송금최소화·입금체크) | 우리 친구들이 단톡방 대신 이 링크를 쓰나? |
| v0.2 | 날짜 투표, 리마인드, 체크인, 볼링 점수→자동 벌칙, 송금 딥링크, 영수증 사진 | 총무가 정산을 10분 안에 끝내나? |
| v0.3 | 명예의 전당, 히스토리, 룰렛, 보드게임 기록, PWA 푸시 | 그룹이 매달 다시 오나? |
| v1.0 | 결산 카드, 연말 결산, 회비 모드, 임시 게스트(G-6) | 공유를 통한 신규 그룹 유입이 생기나? |

**MVP 구현 순서(백엔드):** 카카오 로그인·토큰 → 그룹·초대 → 모임·차수·참석 → 지출·정산 계산(벌칙 없이) → 게임 방·사다리·꽝뽑기 → 벌칙 → 정산 연동.
정산 계산 로직은 순수 도메인 로직으로 분리해서 단위 테스트를 촘촘히 붙인다(돈 문제는 버그 나면 신뢰가 바로 깨짐).

## 9. 리스크 & 대응

| 리스크 | 대응 |
|---|---|

| 카카오톡 인앱 브라우저 로그인 이슈 | 초기에 인앱 브라우저 로그인·리다이렉트 흐름부터 검증 |
| 각자 폰 게임 중 접속 끊김 | 제한 시간 후 자동 배정(R-8), 재접속 시 REST로 상태 복구 |
| 게임 결과 조작 의심 | 서버 생성 결과 + 공개 전 비노출 + 재실행 이력 공개 |
| 정산 금액 분쟁 | 계산 근거(누가 왜 얼마) 항목별 노출, 확정 후 수정 이력 |
| 기존 앱(토스 N빵, 사다리 앱)과 경쟁 | 단일 기능이 아니라 **참석→게임→정산 연결**로 차별화 |
| 계좌 정보 노출 | 그룹 멤버 한정 노출, 송금 딥링크 우선 |
